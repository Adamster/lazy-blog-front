# Тетрис — апгрейд до modern guideline (SRS, хард-дроп, hold, input-слой)

**Дата:** 2026-07-05
**Статус:** дизайн утверждён (выбор владельца: полный modern guideline · guideline-счёт · геймпад + ремап клавиш сейчас · модалка CONTROLS в меню игры)
**Повод:** фидбэк игрока — нет хард-дропа, суровый lock delay, ненастроенный DAS, нет wall-kick'ов / T-спинов / hold, вращение читается как одностороннее, хочется переназначение кнопок и геймпад.

## Кратко

Переводим аркадный Тетрис с сознательно «чистейшего NES-классика» на
**современный guideline-руллсет**, на месте (тот же класс движка, тот же
роут, тот же лидерборд), и добавляем переиспользуемый input-слой
(переназначение клавиш + геймпад) в `features/arcade/shared`, подключённый
пока только к Тетрису.

Архитектурное решение: развиваем существующий headless `TetrisEngine`
(`src/features/arcade/tetris/model/engine.ts`), а не строим параллельный
«modern»-движок — два руллсета означали бы два несопоставимых лидерборда.
Паспорт-комментарий движка («purest classic») переписывается под новый
руллсет.

## 1. Вращение — SRS с полными wall/floor-kick'ами

- Система вращения: **SRS** (Super Rotation System), по
  <https://tetris.wiki/Super_Rotation_System>. ARS рассматривалась и
  отклонена: весь остальной утверждённый пакет (T-спины, B2B, 7-bag, hold,
  guideline-счёт) определён поверх SRS; ARS — линия TGM с другими
  спавн-ориентациями и грейдами вместо очков.
- Существующие спавн-матрицы уже воспроизводят SRS-состояния вращения при
  матричном повороте (проверено для всех семи фигур), так что состояния
  остаются как есть; меняется только `tryRotate`.
- `tryRotate(dir)` перебирает **точные kick-таблицы из 5 тестов с
  tetris.wiki** (при имплементации сверить смещения со страницей вики и
  перекодировать в нашу сетку — у вики +y вверх, у нас вниз):
  - таблица J/L/S/T/Z (на каждую пару состояний from→to по 5 смещений,
    включая floor-kick'и);
  - отдельная таблица для I;
  - O: без киков (поворот — no-op).
- Побеждает первое подошедшее смещение; **запоминаем индекс применённого
  кика и было ли последнее успешное действие поворотом** (нужно для
  детекции T-спина).
- CW = `ArrowUp`/`X`, CCW = `Z` (обе стороны уже существовали; становятся
  видимыми в подсказках и переназначаемыми).

## 2. Хард-дроп + ghost piece

- **Хард-дроп** (по умолчанию `Space`): фигура телепортируется в точку
  падения и **локается мгновенно** — 0 фреймов, без lock delay, без
  возможности сброса. +2 очка за клетку падения.
- **Ghost piece**: точка падения всегда отрисована бледным акцентным
  силуэтом. Новая запись палитры `ghostFill` (accent с низкой альфой,
  резолвится в хуке как остальные токены). Ghost статичен — fallback под
  reduced-motion НЕ нужен.
- **Клавиша паузы уходит со Space** (сознательное отступление от паритета
  «Space — ЕДИНАЯ пауза аркейда» — зафлагировано и утверждено): дефолты
  Тетриса становятся `Space` = хард-дроп, **`P` = пауза**. Всё
  переназначаемо (§7). Экраны menu/over по-прежнему стартуют по
  Enter/Space.

## 3. Hold (сохранение фигуры)

- Клавиши по умолчанию `C` или `Shift` (любой из двух).
- Обмен текущей фигуры ↔ HOLD-бокс; если бокс пуст — вместо неё спавнится
  следующая. **Один обмен на фигуру** — право возвращается при локе.
  «Использованное» состояние рисует превью hold приглушённым (`lockedFill`
  вместо `pieceFill`).
- UI: **бокс HOLD над NEXT** в readout-колонке (тот же паттерн
  `PanelLabel` + превью-канвас). `drawNext` обобщается в
  `drawPreview(ctx, type | null, …)`, переиспользуется обоими боксами.

## 4. Lock delay + перенастройка DAS

- Lock delay: 120 мс без сброса с первого приземления → **500 мс, сброс при
  каждом успешном move/rotate**, лимит **15 сбросов на фигуру** (guideline
  move-reset). После лимита фигура локается сразу при приземлении (без
  дальнейшей форы).
- DAS: 170 мс delay / 50 мс repeat → **133 мс delay / 25 мс repeat**.
- Soft drop остаётся 1 очко/клетка; каденс остаётся `SOFT_DROP_MS` (40 мс)
  с клампом к гравитации как сейчас.
- Кривая гравитации **сохраняется** (NES-таблица кадров + веб-пол 50 мс) —
  уже оттюнена под сайт; guideline-гравитация 20G вне скоупа.

## 5. Рандомайзер — 7-bag

- NES-reroll → стандартный **7-bag**: перемешиваем все семь фигур, раздаём
  по порядку, пополняем по опустошении. Логика `prevPieceIndex` удаляется.
- NEXT-превью остаётся **одно** (панель компактная; 3 превью — возможное
  расширение потом, не в скоупе).

## 6. T-спины + guideline-счёт

- **Детекция T-спина — правило трёх углов**: фигура T, последнее успешное
  действие — поворот, и ≥3 из 4 диагональных углов 3×3-бокса фигуры заняты
  (стены/пол считаются). **Mini** против полного: если оба _передних_ угла
  (сторона, куда смотрит T) не заполнены — это mini, КРОМЕ случая кика на
  пятое (последнее) смещение таблицы — он апгрейдит до полного T-спина
  (стандартное правило).
- **Счёт — полный guideline**, всё × (уровень + 1):
  | Клир                                                | Очки                            |
  | --------------------------------------------------- | ------------------------------- |
  | Single / Double / Triple / Tetris                   | 100 / 300 / 500 / 800           |
  | T-spin mini (без линий) / mini single / mini double | 100 / 200 / 400                 |
  | T-spin (без линий) / single / double / triple       | 400 / 800 / 1200 / 1600         |
  | Back-to-back (цепочки Tetris / T-spin-клиров)       | ×1.5 к очкам клира              |
  | Комбо                                               | +50 × длина комбо × (уровень+1) |
  | Soft drop                                           | +1 / клетка                     |
  | Хард-дроп                                           | +2 / клетка                     |
- Уровень остаётся `floor(lines / 10)`.
- Лидерборд: смена формулы делает новые очки щедрее старого NES-борда —
  принято; борд перезапишется естественно. Без миграции.
- **Строка события**: маленькая транзиентная подпись под readout'ами
  («TETRIS», «T-SPIN», «B2B ×1.5», комбо), чтобы бонусы читались. Движок
  сообщает вид клира в `TetrisStep`; хук/борд показывает её коротко
  (reduced motion уважается простым показом/скрытием, анимация не нужна).

## 7. Input-слой (`features/arcade/shared`)

### Модуль биндингов (`key-bindings.ts`)

- Набор действий (Тетрис): `moveLeft`, `moveRight`, `softDrop`, `hardDrop`,
  `rotateCW`, `rotateCCW`, `hold`, `pause`.
- Дефолты: `←/A`, `→/D`, `↓/S`, `Space`, `↑/X`, `Z`, `C/Shift`, `P`.
  (Поддерживается несколько физических клавиш на действие — дефолтам это
  нужно.)
- Persistence: ключ `localStorage` **`arcade.tetris.keys.v1`**, хранит
  списки `KeyboardEvent.code` по действиям; при загрузке мержится поверх
  дефолтов; битые данные откатываются на дефолты.
- Назначение клавиши **отбирает её** у любого другого действия, которое ею
  владело.
- API generic (параметризован набором действий + ключом хранения), чтобы
  остальные аркадные игры могли подключиться позже; сейчас потребитель —
  только Тетрис.
- Клавиатурный хендлер Тетриса читает живую карту вместо хардкода
  `isLeft/isRight/…`. `KEY_HINTS` меню и `aria-label` канваса генерируются
  из живой карты.

### Модалка CONTROLS

- Пункт CONTROLS в **меню-оверлее** Тетриса (общий `MenuOverlay` получает
  точку расширения) открывает системный `Modal`:
  - по строке на действие: название действия ↔ текущие клавиши;
  - клик по строке → состояние захвата «PRESS KEY…» → следующий `keydown`
    записывается (Escape отменяет захват);
  - кнопка RESET к дефолтам;
  - по дизайн-системе (mono-лейблы 11px/0.12em, контролы 36px, хром
    `Modal`, `.mono-focus`).

### Геймпад

- Поллинг из **существующего rAF-лупа** (второго лупа нет) через
  `navigator.getGamepads()`; edge-детекция по снапшоту кнопок прошлого
  кадра.
- Фиксированный маппинг standard-layout (v1, не переназначаемый):
  D-pad влево/вправо (14/15) + ось 0 левого стика (deadzone ±0.5) =
  движение · D-pad вниз (13) / ось 1 > 0.5 = soft drop · D-pad вверх (12) =
  хард-дроп · A (0) = поворот CW · B (1) = поворот CCW · LB/RB (4/5) =
  hold · Start (9) = пауза. На menu/over любая кнопка = старт.
- Удержания направлений питают то же DAS-состояние, что и клавиатура (вход
  движка — это merge удержаний клавиатуры ИЛИ геймпада; one-shot-действия —
  эджи с любого устройства).

## 8. Вне скоупа (сознательно)

- Слайдеры DAS/ARR в UI (только константы).
- NEXT-превью на 3 фигуры.
- Ремап геймпада.
- Подключение input-слоя к Snake/2048/Hollow-Sloth.
- Guideline-гравитация 20G / варианты lock-out.

## 9. Тесты и гейты

- Движок headless — юнит-тесты (образец: `2048/model/engine.test.ts`):
  kick-таблицы SRS (репрезентативные кики: у стены, у пола, для I-фигуры),
  детекция T-спина и mini включая апгрейд пятым киком, распределение 7-bag
  (каждое окно из 7 — перестановка), guideline-счёт включая цепочки B2B и
  комбо, сброс lock delay + лимит 15 сбросов, мгновенный лок хард-дропа +
  очки за дистанцию, правило одного hold.
- Модуль `key-bindings`: мерж дефолтов, отъём клавиши при ремапе, откат при
  битом сторадже.
- `npm run typecheck` + `npm run lint` в ноль.
- Вручную: проход на клавиатуре + реальном геймпаде; переключение темы
  (палитра включая ghost); проход с reduced-motion; round-trip фулскрина.
